# @ruplot/react API

React **18+** bindings for uPlot (19 recommended). Prefer `@ruplot/react` for app code.
Advanced helpers: `@ruplot/react/unstable` — see the [GitHub README](https://github.com/Avoronov93/react-uplot-core#api-stability-03)
(when to use, remount rules, migration).

## Install

```bash
pnpm add @ruplot/react uplot
```

```ts
import "uplot/dist/uPlot.min.css";
import {
  Chart,
  useCursor,
  useScales,
  type CursorSnapshot,
} from "@ruplot/react";
```

## SSR / hydrate

`createChartStores()` + `getServerSnapshot` are the hydrate contract.

1. **Server:** `const stores = createChartStores()` — render HUD / chrome with
   `useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)` (idle cursor).
   Do **not** mount `<Chart>` on the server (no canvas).
2. **Ship HTML** with the same store identity available on the client (module scope,
   request cache, or serialize nothing — recreate stores only if you also recreate the HUD).
3. **Client:** pass the **same** instance: `<Chart stores={stores} … />`.
   Chart wires uPlot into those stores; subscribers already mounted keep working.

```tsx
const stores = createChartStores(); // share across server render + client hydrate

function CursorHud() {
  const idx = useSyncExternalStore(
    stores.cursor.subscribe,
    () => stores.cursor.getSnapshot().idx,
    () => stores.cursor.getServerSnapshot().idx,
  );
  return <span>{idx ?? "—"}</span>;
}

// Server: <CursorHud /> + placeholder
// Client: <CursorHud /><Chart data={data} options={options} stores={stores} />
```

Interactive: **03 Updates → SSR hydrate**.

### Store batching (no React)

uPlot may update cursor + scales in one turn. ruplot coalesces notifies via
`batchStores` / a microtask turn inside the session — **not**
`unstable_batchedUpdates`. App code can also:

```ts
import { batchStores } from "@ruplot/core";

batchStores(() => {
  stores.cursor.setState(…);
  stores.scales.setState(…);
});
```

## 2. Hooks

All chart hooks (except sync-group helpers) **must run under `<Chart>`** (or `Chart.Plot`).
Store hooks use `useSyncExternalStore` — selecting a slice re-renders **only that subscriber**, not the canvas tree.

### Selector pattern

Every store hook is overloaded:

```ts
useCursor(): CursorSnapshot
useCursor<T>(selector: (snap: CursorSnapshot) => T): T
```

<table className="doc-api-table">
  <thead>
    <tr>
      <th>Parameter</th>
      <th>Type</th>
      <th>Default</th>
      <th>Notes</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code className="doc-type">selector?</code></td>
      <td>
        <code className="doc-type">{"(snap) => T"}</code>
      </td>
      <td>identity</td>
      <td>
        Omit to get the full snapshot. Pass a selector to return a slice
        (e.g. <code className="doc-type">c =&gt; c.idx</code>). Comparison is{" "}
        <code className="doc-type">Object.is</code> on the selected value —
        prefer primitives / stable refs, not fresh objects each call.
      </td>
    </tr>
  </tbody>
</table>

```tsx
// Full snapshot — re-render when any cursor field changes
const cursor = useCursor();

// Narrow — re-render only when idx changes
const idx = useCursor((c) => c.idx);

// Several fields without allocating a new object every time:
const left = useCursor((c) => c.left);
const top = useCursor((c) => c.top);
```

## 3. Composition

Children of `<Chart>` (or standalone imports: `Brush`, `Tooltip`, `SyncGroup`).
`Chart.AutoSize` observes a frame and supplies **both** `{ width, height }`; `Chart.Legend` toggles
series without rebuilding options. `Brush` supports draggable interior bands (`panBand`) and
vertical ranges (`orientation="y"` / `scaleKey="y"`, usually with `bindScale={false}`).
`useCursor()` exposes lean `{ idx, idxs, left, top }` — read values from `data[s][idxs[s]]`.

### `Chart.Brush`

## 7. SSR / hydrate (pre-created stores)

uPlot needs a DOM target, so the **canvas is client-only**. External stores are SSR-safe:

1. On the server (or in a shared module), call `createChartStores()`.
2. Render HUD / chrome with `useSyncExternalStore(store.subscribe, getSnapshot, getServerSnapshot)`.
3. Ship HTML **without** `<Chart>` (placeholder is fine).
4. On the client, pass the **same** instance: `<Chart stores={stores} … />`.

```tsx
const stores = createChartStores(); // module scope or request-scoped

function CursorHud() {
  const idx = useSyncExternalStore(
    stores.cursor.subscribe,
    () => stores.cursor.getSnapshot().idx,
    () => stores.cursor.getServerSnapshot().idx, // idle on server
  );
  return <span>{idx ?? "—"}</span>;
}

// Server: <CursorHud /> + placeholder
// Client: <CursorHud /><Chart data={data} options={options} stores={stores} />
```

`getServerSnapshot()` never changes after create — client cursor updates only `getSnapshot()`.
Demo: **03 Updates → SSR hydrate**.

### Store batching (no React `unstable_batchedUpdates`)

`@ruplot/core` exposes `batchStores` / `store.batch` (also as deprecated alias `batchUpdates`).
Session wraps uPlot hook turns (`setCursor` + `setScale` + …) in one batch and flushes on a
microtask — framework-agnostic, no React dependency in core.
